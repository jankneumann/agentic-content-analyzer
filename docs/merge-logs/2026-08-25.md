### Findings

**Guard-blocked dependency bumps are not CI flakes.** `tests/config/test_cli_runtime_hygiene.py`
encodes compatibility invariants Dependabot cannot see:

- **#497 (chardet `<6`→`<8`)** — `requests` requires `chardet<6`.
  `AssertionError: assert <Version('6')> not in <SpecifierSet('<8,>=5.2')>`
- **#495 (typer `<0.20`→`<0.28`)** — the assertion *is* the migration ticket:
  *"typer 0.20 vendors click as typer._click; migrate src/cli/app.py's get_command
  override to the vendored types before lifting this cap."* The typecheck job
  independently confirms it with 3 mypy `[override]`/`[return-value]` errors at
  `src/cli/app.py:88-94`.

Neither `rerun-checks` nor `refresh-branch` could help — the guard is working as designed.
Both closed with the diagnosis and the unblocking condition recorded on the PR.

**#506's 26 lint errors were one authoring mistake.** Suppressions were written as
`# ruff: ignore[rule-name]` (and `# ruff: file-ignore[...]`), which is not ruff syntax —
`# ruff:` is the *file-level* directive prefix. Ruff rejected each as invalid
(RUF102/RUF103) and then reported the underlying rule unsuppressed: two errors per site,
10 invalid suppressions → 26 errors. Translated every site to real codes
(F401/S108/S607/S608/S310), preserving the author's rationale comments.

Also surfaced a **hidden second failure**: CI runs `ruff check src/` (line 79) before
`ruff format --check src/` (line 82). The check failure meant the format step never ran,
concealing an unformatted `src/cli/backup_commands.py` that would have failed the job on
the very next attempt. Fixed in the same commit.

**#491's `frontend-release` failure was pure base drift.** The PR changes zero files under
`web/`, yet `npm audit` failed — the vulnerability lived in main's lockfile at the PR's
merge base, 116 commits back. Rebasing onto current main fixed it with no code change,
and `frontend-release` now passes. Its one real defect was `no-any-return` from the untyped
optional `anydoc` dependency, fixed with the repo's established
`# type: ignore[no-any-return]` pattern rather than a `cast`, which would assert a
guarantee the untyped call does not make.
