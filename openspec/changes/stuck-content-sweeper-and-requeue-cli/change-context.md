## Design Decision Trace

| Decision | Rationale | Implementation | Why This Approach |
|----------|-----------|----------------|-------------------|
| D7 | Bound stale detection, batch work, lock waits, statements, and retry attempts. | Validated `Settings` fields with documented safe defaults and one timeout-order validator. | Direct Pydantic constraints keep policy validation at process startup and avoid a second configuration layer. |
| D2 | Fence every queue attempt and keep old-worker behavior safe. | A shared `ContextVar` carries the exact claim generation; worker, setup, and operation lifecycle mutations require `(id, in_progress, generation)`, while the database trigger resets every requeue to protocol 1. | Task-local propagation reaches async handlers and `to_thread` work without expanding every handler signature, and guarded updates fail closed after claim loss. |
| D6 | Preserve graph-wide lock order across retry and reconciliation. | Public retry takes graph then root locks; the private connection-scoped primitive verifies that graph lock, takes the target row, mutates on the supplied connection, and sends notification in the same transaction. | A single mutation primitive avoids nested connections and keeps root-to-target ordering observable and testable. |
| D8 | Keep preview persistence-free and distinguish proposed from observed results. | Request defaults `apply` to false; report mode and item projection use closed enums. | The wire contract makes dry-run explicit without adding a reconciliation operation lifecycle. |
| D9 | Make every applied mutation externally auditable without leaking payload data. | Closed item fields include before/after state and retry counts; actions and reasons are enumerated. | A strict schema provides an allowlist that generated clients share. |
| D10 | Ensure deterministic bounded scans and safe continuation. | Request/report bounds cap pages at 100 and use positive content IDs for keyset continuation. | Contract-level limits prevent transports from requesting unbounded work. |
| D11 | Fail closed during rollout. | Apply defaults off in settings and request schema; the endpoint declares a 503 problem response. | A default-off server gate preserves existing behavior and gives rollback a single switch. |
| D12 | Persist ownership and action evidence without coupling retention lifecycles. | Add nullable complete owner/provenance tokens plus an append-only action table that retains IDs without foreign keys. | Legacy writes remain valid, while reconciliation can prove exact ownership and historical evidence survives queue/content retention. |
| D13 | Preserve old-worker safety while introducing claim fencing. | Database triggers increment every queue claim generation and reset every requeue to protocol 1; current workers opt into protocol 2 later. | Trigger-driven defaults cover workers that do not know the new columns and make rollback behavior explicit. |
