### Decisions
1. **Use nested config.type as the only POST discriminator** — It is the existing FastAPI, CLI, web, and test contract.
2. **Keep Obsidian creation and editing worker-local** — Browser paths cannot safely represent or validate worker mounts; existing rows remain manageable by opaque key.
3. **Add Readwise browser quick-add** — Its non-secret options are safe to submit while credentials remain environment-owned.
4. **Extend the durable content-workflows OpenAPI** — One additive executable contract avoids a second contract domain and archive drift.

### Trade-offs
- Accepted a narrow public quick-add UI over exposing every backend field because advanced configuration remains safer in YAML, CLI, or direct API use.
- Accepted documented recovery for incompatible manual tables over rewriting a shipped historical migration because historical migrations cannot repair deployments that already recorded the revision.
