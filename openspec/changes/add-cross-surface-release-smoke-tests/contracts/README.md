# Contract assessment

This change does not modify the canonical workflow OpenAPI:

`openspec/contracts/content-workflows/openapi/v1.yaml`

It adds two operational release-observation fields outside that workflow
contract:

- backend `/health` response: bounded `revision` and allowlisted
  `revision_source` strings;
- served frontend HTML: `release-revision` and `release-revision-source` meta
  values;
- served frontend `release-assets.json`: revision-bound complete JavaScript
  asset inventory with sizes and SHA-256 digests.

For the canonical detached-SHA Railway CLI upload, the frontend revision comes
from `web/release-build.json`, generated by the planned repository stamp command
only after verifying the supplied SHA equals clean detached `HEAD`. The build
embeds `verified_detached_sha` provenance; the release runbook correlates the
same SHA and stamp digest to Railway's SHA-bearing CLI message.

The machine-readable evidence contract is
`release-smoke-evidence.schema.json` in this directory. It is intentionally
restrictive and must be validated before a report is retained or uploaded.

`retired-workflow-mutations.json` is the non-overridable baseline denial policy.
The implementation promotes the same entries to
`config/release_smoke_retired_routes.json`; runtime configuration may add but
never remove entries.

Canonical capability, configured-source, ingestion, and durable-operation
requests continue to use the generated v1 workflow contracts unchanged.
