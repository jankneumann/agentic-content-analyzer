### Decisions
1. **Agent tasks are a canonical operation type** `architectural: agentic-operations` — execute_agent_task was a legacy string handler with no idempotency, cancel, list, or events; registering agent_task.execute in the v2 registry gives all four and removes the ad-hoc re-enqueue.
2. **Approvals are approval.wait child operations with a decision result** `architectural: agentic-analysis` — Denial is a valid outcome, not a failure; the parent resumes from a checkpoint the way pipeline.run resumes on ingestion children.
3. **Defer-until-event generalizes the existing batch parent reset** `architectural: agentic-operations` — OperationService.defer re-polls every second; a human approval can take hours. A wait_on marker plus a child-terminal wake inside the same transaction reuses the summarization.run reset path instead of adding a second notification channel.
4. **Async engine confined to memory strategies** `architectural: agentic-analysis` — Vector and keyword strategies require an async session factory that did not exist; asyncpg is already a dependency. The factory is imported only under src/agents/memory and a test asserts that.
5. **Embedding column follows the configured model** `architectural: agentic-analysis` — agent_memories.embedding was vector(1536) while the default local model is 384-dim; the migration interpolates the dimension at migration time, the documented pg_cron pattern.
6. **Tier: coordinated** — Coordinator reachable with lock, queue, and discover; feature spans queue, agents, storage, and contracts.
