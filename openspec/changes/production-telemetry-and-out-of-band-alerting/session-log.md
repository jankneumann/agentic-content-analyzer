## Phase: Plan (2026-08-02)

**Agent**: codex | **Session**: N/A

### Decisions
1. **Use a dedicated transactional terminal-event outbox** — Existing generic notifications commit separately, accept unsafe open payloads, and provide only process-local SSE delivery.
2. **Implement HTTPS webhook as the v1 sink** — A receiver can honor stable idempotency keys and the transport is deterministic to test without inventing incomplete email identity/configuration.
3. **Capture operation intent with database triggers** — Canonical terminal transitions have worker, cancellation, handler, and maintenance paths; a trigger closes post-commit crash and bypass windows.

### Alternatives Considered
- Extend NotificationDispatcher: rejected because It lacks transactional coupling, dedupe, leases, external delivery, and a closed safe envelope.
- SendGrid email: rejected because The installed dependency has no sender, recipient, or receiver-side idempotency contract in this repository.
- Emit from application hooks after terminal commit: rejected because A process crash or forgotten transition path would lose terminal evidence.

### Trade-offs
- Accepted At-least-once webhook delivery with receiver idempotency over An unprovable exactly-once network guarantee because Stable keys make ambiguous retries safe when the receiver honors the explicit contract.
- Accepted Pipeline-root alert aggregation over Immediate alerting for every failed leaf because Bounded operator noise is more actionable while leaf telemetry remains available.
