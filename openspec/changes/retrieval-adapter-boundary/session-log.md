### Decisions
1. **Adapters return per-leg candidates; fusion, rerank, and tree search live above them** `architectural: retrieval-adapter` — Keeps one RRF implementation for both namespaces and makes shadow comparisons attributable per leg.
2. **Write means index write; system-of-record row inserts stay in the ORM** `architectural: retrieval-adapter` — document_chunks ids are database-assigned and referenced by content_references; the adapter owns embedding and provenance writes only.
3. **No delete verb: replace_parent on write plus orphan reconciliation in improve** `architectural: retrieval-adapter` — Preserves the four-action contract while covering reindex and content deletion.
4. **LanceDB is the second adapter; Infino and turbopuffer are documented future adapters** `architectural: retrieval-adapter` — LanceDB exercises every protocol seam with a mature API; Infino is 0.x with Enterprise-only lakehouse integration; turbopuffer is hosted-only.
5. **Retrieval metrics extend aca evaluate via a retrieval dataset kind and reuse evaluation_results** `architectural: retrieval-evaluation` — Avoids a parallel evaluation surface and keeps report generation working; additive nullable migration limits overlap with the routing work.
6. **Every retrieval setting defaults off; secondary adapter and shadow read are opt-in** `architectural: retrieval-adapter` — Rollback is unsetting settings; production evidence relying on meta.bm25_strategy stays valid.

### Alternatives Considered
- Per-leg strategy generalization of BM25SearchStrategy: rejected because Forbids single-query hybrid with native filters, the property under evaluation.
- Whole-service adapter at search(SearchQuery)->SearchResponse: rejected because Duplicates reranking and tree search per backend and excludes agent memory.
- Infino as the second adapter: rejected because 0.x API, single writer per table, Iceberg integration Enterprise-only; deferred to watch list.
- A fifth mandatory access-tracking action: rejected because Only the memory namespace needs it; modeled as an optional protocol extension instead.

### Trade-offs
- Accepted Larger refactor touching search, indexing, scripts, and memory strategies over Smaller per-leg change because Only the larger change proves the abstraction against two namespaces before a second backend lands.
- Accepted Dual-write consistency surface between Postgres and LanceDB over Rebuild-only sync because Reconciliation in improve plus overlap metrics make drift visible; secondary failures never block ingestion.
- Accepted Shadow reads run post-response and add no request latency over Inline comparison because Cold-start cost on ephemeral containers is measured, not paid by users.
