### Decisions
1. **Vendor the change-graph contract and validate it in two passes** `architectural: change-visualization` — The exported JSON Schema covers shape only. The upstream contract is authored in zod, where referential rules such as 'every edge endpoint is a declared node' live in refinements that do not survive export, so a document with a dangling edge passes the schema and is then rejected by the renderer. Python reimplements those rules so the two validators agree and the failure surfaces at projection, naming the offending id, rather than in CI at render time.
2. **Coverage is a node property; test nodes are not drawn** `architectural: codebase-atlas` — Test functions are 57% of this repository's graph nodes and TEST_COVERS is 96% of its edges, so drawing them turns a picture of the application into a picture of its test suite, and expanding a neighbourhood across them does the same. Coverage rides as a colour and a badge on the covered node instead, which answers 'is this tested' without doubling the graph.
3. **A change that covers nothing produces no document** `architectural: change-visualization` — The contract requires at least one node, so a document showing that nothing is covered cannot exist. A placeholder node would put a claim on the page that no artifact supports, and a relaxed local schema would let the Python and Node validators disagree. The projector writes a coverage report, names the roots it searched, and exits 0, because a tooling-only pull request must not fail CI for being one.
4. **Narration writes prose and cannot write structure** `architectural: change-visualization` — The merge reads a closed set of text keys, so a hallucinated node has no path by which it could be written, and a structural comparison over the document with its prose stripped catches the rest. Stat chips are excluded: a chip is a number beside a diagram, and the comparison can catch an invented id but not an invented quantity.
5. **Defer the Obsidian canvas export, on different grounds than assumed** `architectural: codebase-atlas` — The spike disproved both stated objections. JSON Canvas takes per-node hex colour, so delta and coverage survive, and it takes edge labels; generated node ids are stable across runs, so hand placement could be preserved by a merge rather than being inherently lost. The real reasons to defer are that it duplicates the atlas with strictly less capability, no animation, no walkthrough, no hop tracing and no semantic zoom, and that nobody has asked for it. Revisit if the team works in a vault day to day, where an editable file beats a URL.

### Alternatives Considered
- Ask a model to produce the graph document from the diff, as pr-lens does: rejected because This repository already computes its call graph from AST, tree-sitter and ts-morph, so inference would trade ground truth for a guess and determinism for a sample.
- Reimplement the SVG renderer in Python: rejected because Its hard part is determinism, not drawing: text measured from a table, fixed lane widths, rounded coordinates. Reproducing it would mean reproducing its bugs.
- Draw test nodes and their TEST_COVERS edges by default: rejected because They are the majority of the graph; the application would be hidden inside its own tests.

### Trade-offs
- Accepted A one-hop neighbourhood over Two or more hops because Two hops on this graph yields several hundred nodes for a routine change. Wider neighbourhoods are the atlas's job, where a hop slider already exists.
- Accepted Rendering through a pinned npm package over A single-language pipeline because Determinism already solved upstream, against a Node dependency in a build-time script only.
