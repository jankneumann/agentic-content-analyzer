# Learning: ri-04

## Decisions
- **Merged the cumulative RI-01 to RI-04 stack through one gated PR**: PR #472 landed the whole worktree chain on main (merge commit ee13ac8a) after all six required checks passed.
- **Anchored the release-smoke contract to a durable location**: Promoted the evidence schema and retired-mutation baseline to `openspec/contracts/release-smoke/` so the runtime parity guard no longer depends on the archived change directory.
- **Made the rest CI shard own the release-smoke toolchain**: Provisioned Node + npm ci and the Playwright/Chromium extra for the rest shard so its frontend-build and real-browser tests execute.

## Recommendations
- Give release-smoke its own CI tier and pytest marker instead of relying on the exclusion-defined `rest` shard, which silently absorbs new heavyweight suites.
- Keep durable executable contracts under `openspec/contracts/`; forbid tests from reading `openspec/changes/` or `openspec/changes/archive/`.
- Route roadmap bookkeeping through a non-main branch — any push to `main` triggers a Railway production deploy without path filtering.
- Continue RI-05 (real ingestion CI tiers) on top of merged main.
