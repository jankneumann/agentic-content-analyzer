# Learning: ri-06

## Decisions
- **Consume gen-eval as an external tool, not a dependency**: Thin runner: check in descriptor + scenarios + gate script; resolve the framework from ACA_GEN_EVAL_PROJECT (default sibling agentic-coding-tools/packages/gen-eval) at run time. ACA's uv.lock stays resolvable with no sibling checkout, which CI, Railway, and Docker require.
  - Rejected: [tool.uv.sources] path dependency - broke uv lock/sync on standalone clones in agentic-assistant and was removed under its ADR 0006
  - Rejected: Vendor a copy of gen-eval into ACA - duplicates an externally owned, actively changing framework
  - Rejected: Reimplement a minimal repo-native runner - discards the schema and evaluator for no benefit
- **Invoke python -m gen_eval, never the gen-eval console script**: The package declares gen-eval = 'gen_eval.__main__:main' but main is async def main(args: argparse.Namespace), so the console script always raises TypeError: main() missing 1 required positional argument: 'args'. Only the if __name__ == '__main__' path wires parse_args() + asyncio.run(). Verified by running both forms. The module form makes this change independent of an upstream fix.
- **Three-state runnability probe; a crash is never an absence**: available / absent / broken. absent skips advisorily locally and hard-fails under ACA_GEN_EVAL_REQUIRE; broken hard-fails everywhere. CI pins the sibling checkout to a recorded ref so absent cannot occur silently.
  - Rejected: Copy the precedent's two-state probe - it conflates broken with absent
- **Single-source the production mutation guard on ri-04's target policy**: Mutating categories consume src/release_smoke/models.py TargetClass plus the production_target_ids / production_origins deny registries and their validators. One place enforces 'production is not a mutation target'.
  - Rejected: A gen-eval-specific target model - a second guard that can drift from the release gate's
- **Validate the report repo-side before trusting --fail-threshold**: A suite that discovers zero scenarios yields a vacuous 100% pass rate. A durable report schema under openspec/contracts/cli-gen-eval/ plus scripts/validate_gen_eval_report.py assert schema validity, minimum scenario and per-category counts, and interface coverage before the threshold.

## Blockers
- The agentic-assistant gate this item was modelled on reports SKIP exit 0 against a complete gen-eval checkout, because its runnability probe is the broken console script and its --scenario flag does not exist in gen-eval's argparse (suites come from the descriptor's scenario_dirs). Reproduced: 'eval-gate: SKIP - not runnable (stub checkout?)', EXIT=0. → Adopted the topology but not the probe semantics. D2 fixes the invocation form, D3 makes broken fatal, D4 drops the non-existent flag and uses --categories. Worth reporting upstream to agentic-coding-tools and to agentic-assistant, whose gate has never actually evaluated anything.

## Recommendations
- Implementation starts at Phase 1 (framework boundary) - it gates every later phase and is the only part with an external failure mode.
- File the console-script defect against agentic-coding-tools and the silently-green gate against agentic-assistant; both are independent of this change landing.
- The roadmap acceptance outcome names 'operation status'; the implemented command is 'aca operations get'. Scenarios target the real name (D7) - do not add an alias.
- ri-07, ri-10, and ri-11 all depend on ri-06. ri-11 in particular expects 'executable compatibility evidence from the release and CLI evaluation suites', so the retained report artifact from Phase 5 is its input.
