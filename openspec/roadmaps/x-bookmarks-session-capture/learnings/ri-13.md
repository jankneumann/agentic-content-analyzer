# Learning: ri-13

## Decisions
- **Follow-up operations from a worker thread**: src/queue/follow_up_operations.py: the canonical ingestion handler lends its running loop and OperationService through a ContextVar that to_thread copies; submissions run via run_coroutine_threadsafe with a 30s timeout; refused on the loop's own thread; unavailable outside a worker, never inline
- **References always, expansion when enabled**: each written bookmark stores content_references for its article links in a savepoint (identifier refs for arXiv/DOI/S2, URL-only otherwise); with expand_links, distinct new links become UrlIngestCommand operations tagged x-bookmark with key x_bookmarks.link:<sha256(url)>
- **Bounded and value-free**: x_bookmarks_max_expanded_links (default 50); skips X self links, twimg media, non-http, feeds and playlists; warnings link_expansion_capped/failed carry counts only; codes added to sanitizer, alert model and schema together

## Deviations
- Plan: submit via OperationService from adapter code → Actual: worker loop binding (reason: OperationService is async while the orchestrator runs in to_thread; asyncio.run in the thread was ruled out)
- Plan: additive details only → Actual: SafeIngestionDetails gains references_recorded, links_submitted, links_skipped in the OpenAPI contract (reason: sanitized results must carry the new counts; regenerated outputs)

## Recommendations
- Capped or failed links are not retried because their rows are known; a later item could re-expand unresolved references
- References link to articles only after aca manage resolve-refs
- Pre-existing: tests/mcp/__init__.py shadows the mcp library when collected with tests/unit
