# Learning: ri-03

## Decisions
- **Workstation role is patch-only**: newsletter-session-writer grants only patch on secret/data/newsletter; AppRole newsletter-workstation, token TTL 900s, secret-id TTL 90 days
- **Worker gains patch on the shared app role**: newsletter-worker (read + patch) attached to newsletter-app beside newsletter-read, so the API and worker can persist rotations
- **hvac kv.v2.patch() is forbidden**: it needs read + update; all writers must use BaoSink's raw merge-patch PATCH

## Deviations
- Plan: separate worker AppRole → Actual: extra policy on newsletter-app (reason: API and worker share one role_id and the session-sync endpoint also patches)

## Recommendations
- Operator must run scripts/bao_seed_newsletter.py --with-session-roles once on gx-10
- Live check on gx-10: bao kv get with a workstation token returns 403 and aca auth gmail --to bao succeeds
- KV v2 ACLs are per path, so a leaked workstation credential can overwrite but not read other keys
