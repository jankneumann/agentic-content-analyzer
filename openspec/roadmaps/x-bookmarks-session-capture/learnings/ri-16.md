# Learning: ri-16

## Decisions
- **Classifier reads the failed operation's result**: classify_terminal_event classified failed operations from status alone as operation_failed; failed ingestion alerts now carry their safe result codes after operation_failed
- **Closed remediation field**: optional remediation_command (aca auth session substack|x) on the alert envelope, allowed only on ingestion.execute alerts with a credential code; omitted when unset so other alerts serialize unchanged
- **Pipeline aggregation bypass**: alerts carrying a remediation command skip pipeline child suppression, so the scheduled pipeline does not swallow an expiry
- **Single refresh-command table**: SESSION_REFRESH_COMMANDS and refresh_command_for() in src/ingestion/credential_failures.py; status rows and the Substack adapter read it

## Deviations
- Plan: only add two codes to enums → Actual: classifier and pipeline routing changed too (reason: widening the enums alone changed nothing because failed operations never read their result)
- Plan: migration for closed codes → Actual: no migration or contract regeneration (reason: DB checks, telemetry key validation and the OpenAPI diagnostic are not closed over codes)

## Recommendations
- ri-12: use command_key x_bookmarks and raise SessionExpiredError / CredentialsMissingError; the alert then names aca auth session x
- Follow-up: resync the alert envelope schema with the model (system_check, Obsidian and backup codes) and add a parity test
- ri-17: document remediation_command and the two credential codes
