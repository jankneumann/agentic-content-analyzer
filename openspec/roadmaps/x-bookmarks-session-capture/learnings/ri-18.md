# Learning: ri-18

## Decisions
- **Own httpx post path instead of substack_api**: the library can only authenticate from a cookies file on disk; _fetch_archive and _fetch_post_detail go through _get_with_session so every post request carries the live cookie
- **Paid-only substack source fails closed without a cookie**: CredentialsMissingError / credentials_missing after one bounded refresh; real_ingest_policy marks substack credentialed
- **Teaser detection and upgrade**: audience only_paid/founding with missing body or <80% of wordcount is a teaser; next authenticated run replaces it, deletes summaries, resets status to parsed (filtered_out kept), reindexes
- **403 disambiguation**: a 403 on a post or archive re-runs the session probe once; live session means per-post access denied (keep teaser, continue), dead session means session_expired with zero rows

## Deviations
- Plan: no pacing → Actual: substack_request_delay_s (default 1.0s) between post-detail requests (reason: host review: runs use the operator's own paid account and the old library slept 2s)
- Plan: any post 403 is a dead session → Actual: probe-disambiguated (reason: host review: a tier-restricted post must not fail the whole run)

## Recommendations
- Live check with a real paid subscription to confirm teaser/full signals and whether custom domains accept substack.sid
- Drop the now-unused substack-api dependency in a later cleanup
- ri-16: add credentials_missing and session_expired to the alert code enums together
