# Learning: ri-05

## Decisions
- **Conservative dead-session predicate**: 401; 403 without cf-mitigated; redirect to /sign-in or /account/login; 2xx text/html from a JSON endpoint; only judged on requests that carried the cookie
- **Refresh once, retry once, then fail closed**: provider.refresh() then one retry if the cookie changed; else mark_rejected() and SessionExpiredError; ingest_content probes, fetches all, then persists, so expiry yields zero rows and code session_expired
- **Reusable credential failure types and codes**: src/ingestion/credential_failures.py: CREDENTIALS_MISSING, SESSION_EXPIRED, CredentialFailureError, SessionExpiredError; result_sanitizer admits both codes

## Deviations
- Plan: fail closed when the Substack cookie is missing → Actual: keep today's warning; readiness reports credentials_missing (reason: the substack_api post path never sends the cookie, so a cookie-less run fetches the same bodies)
- Plan: per-source code x_bookmarks_credentials_missing → Actual: shared credentials_missing (reason: readiness is already per source)

## Recommendations
- Paid Substack post bodies are fetched logged out today: substack_api Newsletter/Post get auth=None. Authenticate that path, then make cookie-less runs fail closed (follow-up)
- ri-11/ri-12: reuse CredentialFailureError, session_expired, mark_rejected/mark_verified, and the fetch-then-persist shape
- ri-16: add session_expired and credentials_missing to WorkflowAlertDiagnosticCode and the alert schema enum together
- ri-17: remove docs mention of aca ingest substack-sync --session-cookie (cookie on argv)
- Unreachable legacy path persists a session_cookie into pgqueuer_jobs.payload and Langfuse inputs; remove it
