# Learning: ri-09

## Decisions
- **Derive alerts from durable terminal evidence**: Canonical operation and reconciliation transitions now feed an append-only, attempt-aware outbox, closed classifier, bounded telemetry, and idempotent webhook delivery.
- **Keep external projection allowlist-first**: The signed envelope and staging receipt carry opaque identifiers, stable codes, bounded counters, and trusted diagnostic provenance without secrets or user content.
- **Scope pooled-database leadership to a transaction**: Worker maintenance uses a transaction advisory lock, preventing a PgBouncer backend from retaining leadership after cancellation or deployment replacement.

## Blockers
- Fresh managed PostgreSQL rejected an unconstrained-vector HNSW index and optional pg_search extension creation. → Bootstrap now distinguishes optional provider capability misses from real migration defects and skips the invalid legacy vector index.
- A session advisory lock survived in a pooled backend after its deployment was replaced. → Leadership is transaction-scoped and regression tests prove it ends before sink I/O and on cancellation.

## Deviations
- Plan: Staging validation was expected to exercise the already-reviewed implementation. → Actual: The live run found and closed managed-database bootstrap and pooled-lock lifecycle gaps before producing evidence. (reason: These behaviors require a real managed provider and connection pool to reproduce.)

## Recommendations
- Reuse the closed terminal-event and alert contracts for RI-10 Obsidian ingestion failures.
- Keep staging verification revision-bound and isolated from production for future releases.
